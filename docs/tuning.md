# 调参指南

## loop_passes（循环次数）

| passes | 效果 | 适用 |
|---|---|---|
| 1 | 退化为普通 Transformer | 对比基线 |
| 2 | 深度 +50%，算力 +50% | 轻量循环 |
| 3 | 深度翻倍（参考值） | 笔记本本地 |
| >=4 | 深度继续涨，收益递减、延迟线性涨 | 极致小参 |

经验：passes 从 1 加到 2~3 收益最明显，之后边际递减。先测 2 和 3，再决定要不要继续加。

## top_k（MoE 激活专家数）

- top_k 越大，激活参数越多、质量越高、算力越贵。
- 稀疏比 = n_experts / top_k，参考 256/8 = 32x。
- 调小 top_k 省算力，但要留意负载均衡损失是否还能收敛（见 README 干货块 C 坑 ③）。

## drafter K（草稿长度）

- 加速比 ≈ K / (1 + K / draft_speedup)。
- K 太小，主模型并行验证的优势没发挥；K 太大，拒绝后浪费的草稿算力反超收益。
- 工程上按草稿 top-1 命中率动态选 K：命中率高（>0.7）就多猜几个，低就少猜。

## quant format

- `mxfp8`：8-bit，精度优先，适合 embedding / 输出头 / 门控。
- `nvfp4`：4-bit，体积优先，适合 MoE 专家 FFN 的稠密矩阵。
- 按层敏感度混用：关键层 FP8、大头 FP4（README 干货块 E）。
